# Аналитика: что собирается и что не собирается

Документ описывает архитектуру сбора продуктовой статистики. Показан **до** подключения
сервера — чтобы можно было утвердить или поправить состав данных.

## Принцип

Данные разделены на два непересекающихся потока.

**Остаётся на устройстве женщины, никуда не уходит:**

- дата последней менструации, длина цикла, длительность менструации, регулярность;
- день цикла и предполагаемая фаза;
- ответы на пять вопросов;
- определённый режим тела и совпадение с фазой;
- свободные тексты вечернего check-in;
- вся история наблюдений.

**Уходит на сервер:**

- название события (одно из четырнадцати, список ниже);
- дата события (только день, без времени);
- источник — значение из `?source=` в адресе.

Больше ничего. Ни идентификатора, ни фазы, ни ответов, ни текстов.

Пример полного тела запроса:

```json
{ "event": "RETURN_D1", "date": "2026-08-29", "source": "womenclub" }
```

## Список событий

| Событие | Когда отправляется | Как часто |
|---|---|---|
| `OPEN` | открытие сайта | не чаще раза в сутки с устройства |
| `START` | нажата кнопка начала опроса | при каждом проходе |
| `RESULT` | показан экран результата | при каждом проходе |
| `TRY_TODAY` | нажата «Попробую сегодня» | раз в сутки |
| `FIT_YES` / `FIT_PARTLY` / `FIT_NO` | ответ на вопрос «насколько это похоже на тебя» | раз в сутки |
| `EVENING_START` | открыт вечерний check-in | раз в сутки |
| `HELPED` / `NO_CHANGE` / `DID_NOT_FIT` | ответ на вопрос об эффекте дня | раз в сутки |
| `EVENING_DONE` | вечерний check-in сохранён | раз в сутки |
| `RETURN_D1` | первое возвращение в другой календарный день | один раз за всё время |
| `RETURN_D7` | возвращение на седьмой день от первого визита или позже | один раз за всё время |

Ограничение «раз в сутки» существует, чтобы перезагрузка страницы не накручивала счётчики.

## Как считается возврат без идентификатора пользователя

В браузере хранятся три служебные записи:

```
ritm.an.first  = "2026-08-27"          дата первого визита
ritm.an.flags  = { "d1": true, ... }   какие разовые события уже отправлены
ritm.an.source = "womenclub"           источник первого визита
```

При открытии сайта приложение сравнивает сегодняшнюю дату с датой первого визита. Если
прошёл хотя бы день и `d1` ещё не отмечен — уходит событие `RETURN_D1`, а флаг ставится,
чтобы больше не повторялось. То же для `RETURN_D7` на седьмой день.

Сервер получает только «сегодня кто-то вернулся на второй день из аудитории womenclub».
Кто именно — на сервере неизвестно и не вычисляется.

Важная оговорка: локальная метка выполняет ту же роль, что и браузерный идентификатор,
просто она никогда не покидает устройство. Формулировка на экране приватности написана
именно так — «не передаётся», а не «не существует».

## Источник трафика

Ссылка для каждого выступления своя:

```
https://gaudialis55.github.io/moy-ritm-segodnya/?source=womenclub
https://gaudialis55.github.io/moy-ritm-segodnya/?source=business
https://gaudialis55.github.io/moy-ritm-segodnya/?source=moms
https://gaudialis55.github.io/moy-ritm-segodnya/?source=wellness
https://gaudialis55.github.io/moy-ritm-segodnya/?source=banya
```

Источник запоминается при первом визите и дальше подставляется во все события этого
устройства — даже если женщина потом зайдёт по обычной ссылке без параметра. Так возвраты
остаются привязаны к той аудитории, из которой человек пришёл. Без параметра источник
записывается как `direct`.

Значение источника фильтруется: только латиница, цифры, дефис и подчёркивание, не длиннее
32 символов. Произвольный текст в него подставить нельзя.

## Что происходит, пока сервера нет

События складываются в очередь `ritm.an.queue` в браузере и печатаются в консоль. Ничего
не теряется: как только в настройках появится адрес приёмника, очередь уйдёт целиком.
Это позволяет протестировать всю воронку на себе и знакомых до оплаты инфраструктуры.

Очередь ограничена 200 событиями, старые вытесняются.

## Как поднять приёмник событий

Пять шагов. Первые четыре делаются в браузере и требуют вашей учётной записи.

**1. Завести аккаунт и проект.** На [supabase.com](https://supabase.com) зарегистрироваться,
создать новый проект. Регион выбрать ближайший, пароль базы сохранить в надёжном месте —
он понадобится только для прямого доступа к базе, в коде сайта его не будет.

**2. Создать таблицу и политики.** Открыть **SQL Editor**, вставить целиком содержимое файла
`analytics-setup.sql` и выполнить. Он создаёт одну таблицу `events`, включает защиту строк
и раздаёт права: публичный ключ может только добавлять события, читать их может только
вошедший пользователь.

**3. Создать себе доступ к статистике.** **Authentication → Users → Add user**, указать
свою почту и пароль, включить «Auto confirm user». Это единственная учётная запись
в проекте — под ней открывается админ-панель.

**4. Скопировать два значения.** **Project Settings → Data API**: `Project URL`
и ключ `anon public`.

**5. Вписать их в код.** В `index.html`, блок `CONFIG.ANALYTICS`:

```js
ANALYTICS: {
  ENABLED: true,
  ENDPOINT: "https://ВАШ-ПРОЕКТ.supabase.co/rest/v1/events",
  API_KEY: "eyJhbGciOi...",   // ключ anon public
  DEBUG: false
}
```

И в `admin.html`, блок `CONFIG`:

```js
var CONFIG = {
  SUPABASE_URL: "https://ВАШ-ПРОЕКТ.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi..."
};
```

После этого события начнут уходить в базу, а накопленная в браузерах очередь отправится
при первом же открытии сайта.

## Кто и что может увидеть

| Кто | Что доступно |
|---|---|
| любой посетитель сайта | ничего: публичный ключ разрешает только добавлять события |
| вошедший в админ-панель | вся обезличенная статистика |
| владелец проекта Supabase | то же самое плюс прямой доступ к базе |

Админ-панель `admin.html` **не публикуется вместе с сайтом** — она есть только в вашей
папке проекта и внесена в `.gitignore`. Даже если файл когда-нибудь попадёт в открытый
доступ, без входа он ничего не покажет.

**Про публичный ключ `anon public`.** Он лежит в коде страницы, и это нормально: сам по
себе он не даёт читать данные. Ключ `service_role` в код класть нельзя никогда — он
обходит все политики.

**Честная оговорка про накрутку.** Публичный ключ позволяет добавлять события кому угодно,
кто заглянет в исходный код. Ограничения в таблице отсекают мусор — принимаются только
известные коды событий и аккуратный формат источника, — но нарисовать себе лишние
`OPEN` технически возможно. Для пилота это приемлемо; если статистика станет основанием
для серьёзных решений, приём событий стоит перенести на свой обработчик с ограничением
частоты запросов.

## Известные искажения статистики

Это важно учитывать при чтении цифр.

- **iPhone занижает удержание.** Safari удаляет хранилище сайта после недели без визитов.
  Женщина, вернувшаяся на восьмой день, будет посчитана как новая, а `RETURN_D7` не уйдёт.
  Частично лечится добавлением на домашний экран — об этом стоит говорить со сцены.
- **Одна женщина с двух устройств** считается как два человека.
- **Малые числа.** При 40 участницах разница между 15% и 25% удержания статистически
  неразличима. Смотреть стоит на порядок величины и на кратную разницу между аудиториями.
- **Блокировщики рекламы** могут резать запросы к стороннему домену, часть событий не дойдёт.

## Настройка в коде

Блок `CONFIG.ANALYTICS` в начале скрипта `index.html`:

```js
ANALYTICS: {
  ENABLED: true,      // false — не собирать вообще ничего
  ENDPOINT: "",       // адрес приёмника; пусто — события только копятся локально
  API_KEY: "",        // для Supabase — ключ anon public
  DEBUG: true         // печатать каждое событие в консоль браузера
}
```

Смена приёмника на другой (например, российский) — это замена `ENDPOINT` и `API_KEY`.
Остальной код не меняется.
